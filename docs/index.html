D4 Optimizer

Paragon board optimization for Diablo IV

Maxroll, D4Builds and Mobalytics all let you click paragon nodes by hand. None of them tell you which nodes to click. This project closes that gap: given a class, a point budget and a set of glyphs, it searches board selection, board rotation, entry gate, glyph assignment and node purchases together.

Why it is a real search problem

A glyph counts a specific stat, but only from nodes you purchased inside a Manhattan-distance-5 diamond around its socket. Every 5 of that stat in range pays out the glyph's coefficient. So a mediocre node inside the diamond can beat a stronger node outside it, and where you place the socket depends on which nodes you intend to buy. That mutual dependence is what stops this being a shopping list.

Damage compounds it. Bonuses do not simply add: they fall into buckets that add internally and then multiply against each other. Adding crit damage to an already enormous crit pool is worth far less than the same number landing in an empty bucket.

Damage buckets, straight from the data

The classification that is usually treated as community knowledge turns out to be encoded in Blizzard's own attribute names. Matched pairs exist:

Damage_Type_Percent_Bonus                 →  additive
Multiplicative_Damage_Type_Percent_Bonus  →  its own multiplier
Bucketed_Multiplicative_Damage_Type       →  explicitly bucketed

Applied across the 373 attributes used by nodes and affixes: 84 additive, 19 separate multipliers, 8 crit, 7 attack speed, 1 vulnerable. Tooltips corroborate it, marking bonuses [x] for separate multipliers and [+] for additive.

Reading a board from a screenshot

The extractor fits the node lattice, then slides a 21×21 window across it, scoring every position against all 10 board layouts in 4 rotations. It only accepts a near-perfect match, because a wrong alignment cannot reproduce a known 441-cell layout by accident. A frame that does not clear the bar is reported as a failed read rather than guessed at.

On honesty in the model. Uptime assumptions for conditional bonuses, such as how often a build is Berserking or Fortified, are genuine judgement calls. They live in a visible UPTIME table rather than being buried in the objective, so they can be argued with and tuned. Open questions are listed in the repository README rather than quietly smoothed over.
